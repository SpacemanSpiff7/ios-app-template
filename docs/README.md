# Docs map

Keep one current source per concern. Mark a retained historical decision superseded and link its replacement.
STATUS stays short; completed task/verification detail belongs in git history or linked evidence.

| File | Read when |
|---|---|
| PRODUCT.md | Planning scope, vocabulary and the primary task |
| DESIGN.md | UI structure, controls, style choices and accessibility |
| DELIGHT.md | Adding motion or haptics |
| EDITING.md | New, saved and nested draft editors |
| ASYNC_WORK.md | Network requests, cancellation, deadlines and diagnostics |
| ARCHITECTURE.md | Changing modules, ownership or persistence |
| BACKLOG.md | Open work and acceptance criteria |
| STATUS.md | Resuming work; current verified source, next action and open gates |
| GOTCHAS.md | Diagnosing a trap already encountered |
| RELEASE.md | Signed artifacts, device checks and distribution |
| api/README.md | Grounding an Apple API before using a new signature |
| specs/ | Dated feature specs while their work is active |
| decisions/ | Architecture/style decisions and rejected alternatives |
| ops/ | Dated evidence while a gate is open |

Project-wide instructions live in CLAUDE.md; scoped rules in .claude/rules/.
Record corrections through /docs-debrief and classify them before proposing a template change.
Link changing versions/counts to configuration or verification manifests rather than copying them across documents.
